            The problem

            Monitoring watches the system. Nobody watches the conversation.

            An incident is decided in a room, out loud, under pressure. A number gets recited from memory. A theory gets restated until it sounds settled. A destructive action gets proposed on top of it. Every one of those steps is invisible to a dashboard, because none of them is a metric.

            AEGIS is not a notetaker and not an assistant waiting to be asked. Nobody talks to it. It listens, and the only evidence it is working is that it stays quiet until the moment it shouldn't.

            How it thinks

            Interpretation, authorization and execution are different jobs.

            The LLM converts messy speech into typed claims. It never outputs a risk level and has no field in its response schema in which it could. Every risk decision is made by Python comparing typed fields. Every consequential action waits for an explicit human utterance.

            • LLMSpeech → typed claims: facts, hypotheses, proposed actions, decisions.
            • PythonFour deterministic checks over typed fields produce the verdict and its reasons.
            • GovernorOne intervention per 45s window, scheduled by utility, packed into 512 bytes.
            • HumanNothing is authorised without an explicit utterance naming or answering the action.

            AEGIS has no execution surface at all — its entire outbound vocabulary is join a call, say this, leave.

            Blast radius

            Direct dependents are not the blast radius.

            Naming only what reads the changed schema understates the damage. A multi-source reverse BFS over the transposed dependency graph separates direct breakage from the cascade, and calls out the entry points a failure reaches — because a failure that reaches one is a failure a user sees.
